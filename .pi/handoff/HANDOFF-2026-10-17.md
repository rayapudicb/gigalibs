## 1. Rules that are never broken

Breaking any of these is a failed handover, whatever else is achieved. When a rule and a goal conflict, keep the
rule, stop, and tell the owner.

### 1.1 Authority

1. **Commit only when the owner's message is the word "commit"** (or plainly contains it as an instruction, such as
   "commit to save W1-A"). "Proceed", "continue", "approved" and "ok" are not "commit". Never push, never amend a
   commit, never rebase, never force anything, never use `--no-verify`.
2. **The owner runs every deploy.** You build, back up, prepare, run `--check`, and hand the owner one exact command.
   You never run `deploy-uat.sh --deploy`, `docker compose up|down|restart|rm`, or anything that changes a running
   container, image in use, volume, network or the UAT database.
3. **UAT is production** (plan v3 decision 0.7a). Your access to UAT data is read-only, and only through this form:

   ```bash
   docker exec -e PGOPTIONS='-c default_transaction_read_only=on' gigalibs-configuration-local-uat-postgres-1 \
     psql -X -U gigalibs -d gigalibs -At -c "<one SELECT>"
   ```

   Any change to UAT data is an owner-run script with a backup first. Write the script, test it on a throwaway
   database, card it, and hand it over.
4. **Nothing changes without an approved card.** A new piece of work starts as a card from `.pi/tasks/TEMPLATE.md`.
   Show it to the owner and wait for an explicit approval ("approved 120xx") before changing product code. Stay inside
   the card. A decision that the card, plan v3 or the owner has not settled is the owner's: stop and ask.
5. **The order of work is fixed**: `docs/plans/gigalibs-execution-plan-v3.md` and `docs/plans/phase-1-sizing.md`.
   Do not reorder, merge, skip or "also quickly do" items. Section 6 below lists what comes next.
6. **Independent Security review before every deploy.** The producer is never the only reviewer of tenancy,
   authentication, permissions, secrets, migrations, external actions or deployment. The reviewer is a separate,
   read-only session (another model or another agent instance) that reads the diff and the card and reports findings
   with file:line evidence and a verdict. Every Medium or higher is fixed, or the owner explicitly accepts it, before
   the deploy. Lows are fixed or recorded on the card as deferred, with a reason.

### 1.2 Zero mock, zero hard-coding (AGENTS.md "Delivery rules")

Refused in any code that production can reach:

- mock or sample data, placeholder rows, "demo" fallbacks, fake provider results, `return []` or `return {}` standing
  in for unbuilt logic, `TODO: implement` stubs presented as done;
- fallback database URLs, default tenants, default users, embedded passwords, keys or tokens, `|| 'localhost'`
  defaults for anything that must be configured;
- `if (process.env.NODE_ENV !== 'production')` branches that change business behaviour;
- local-only persistence (in-memory maps, files) for business data. Durable state lives in PostgreSQL with RLS.

In tests:

- mocks live only in `*.spec.ts` / `*.test.ts` files and in test-only folders that the build excludes (example:
  `modules/physical-operations-cmms/apps/api/src/test/`, excluded in that package's `tsconfig.json`);
- never add `it.skip`, `describe.skip`, `.only`, `xit` or `test.todo` to get green;
- never weaken, delete or rewrite an assertion so a failing test passes. A failing test is a finding: fix the code,
  or stop and report it;
- a new behaviour gets a test that **fails on the old code and passes on the new**. Say which tests those are.

In TypeScript: no `@ts-ignore`, `@ts-expect-error`, `as any` or non-null `!` to silence the compiler in production
code. Fix the type.

### 1.3 Safety in the repository

- **Other sessions' files:** never stage, edit, format, move or delete them. Today they are:
  - `apps/workflow-platform/app/(app)/maps/page.tsx`;
  - `apps/workflow-platform/components/auth/AuthAtmosphere.tsx`;
  - `apps/workflow-platform/components/communications/OmnichannelSoftphoneDrawer.tsx`;
  - `apps/workflow-platform/components/geospatial/PlantSpatial3DViewer.tsx`;
  - `apps/workflow-platform/public/`, `vendor/`, `apps/workflow-platform/__tests__/vendor-copilotkit.test.ts`;
  - `.pi/handoff/proof-scripts/` in the main worktree, `.pi/handoff/HANDOFF-2026-10-08.md`, `.pi/tasks/WI-OI-120y.md`;
  - the owner's untracked folders (`Claude outputs/`, `modules/communications-textfly/`, `modules/platform-rbac/`,
    `scratch/`, `universal-invoicing-demo*`).

  Always stage by explicit path (`git add -- <path> ...`), never `git add -A`, `git add .` or `git commit -a`.
- **Never edit a deployed migration.** Use a new, forward migration. CMMS `000020_canonical_maintenance_requests` has
  never been deployed (UAT is at 19), so it was amended in place for W1-A. From the moment the owner deploys W1-A it
  is frozen like every other migration.
- **Generated files are regenerated, never hand-edited:**
  - windows: `node scripts/generate-windows.mjs <module>`;
  - manifests, roles, gateways, navigation, permission catalogue: `node scripts/module-manifests.mjs --write`
    (without `--write` it audits).
- **Secrets:** never open, print, copy into chat, or commit `.env*` files or their values. Never put a password on a
  command line. Passwords are read with `read -rs`. The test accounts' shared password and the platform owner's
  password have appeared in transcripts. Never repeat them; the owner is asked to rotate them.
- **Builds read the worktree.** While any `build-*.sh` runs in a worktree, do not edit any file in that worktree.
  Do not pipe `refresh-source-identity.sh` into `head`: it can cut the script off half-way.
- **One implementation writer at a time.** Reviewers and auditors are read-only.
- **Shell:** the owner's shell is zsh. An unquoted `$var` holding several lines is **not** split into words. Loop with
  `while IFS= read -r f; do ...; done < list.txt`. A line of `======` is a zsh error: do not echo it.

### 1.4 Honesty

- Run a check before you say it passes, and quote the result line (for example `Tests 1450 passed`).
- A failure is reported as a failure, with the output. A skipped step is reported as skipped, with the reason.
- Statuses follow evidence (plan v3 rule 8): Built, On UAT, Done (only with the owner's recorded acceptance),
  Replaced. Never write "Done", "production-ready" or "complete" without that evidence.

### 1.5 How to talk to the owner

The owner asked for this explicitly (2026-10-16): too many options make them doubt what to do.

- End every message with **exactly one** clear next step for the owner: one word to reply (for example **commit**),
  or one complete command to paste, or "nothing needed from you now".
- No option menus. Recommend one path; raise a decision only when it is due, as one question with your
  recommendation.
- Plain language. Short. Say what changed, the evidence, and the one next step.
- Commands handed to the owner are complete: no `<placeholders>`. In zsh `<...>` is a redirection and fails.

## 5. How work is done here (the loop every card follows)

1. **Card first.** Purpose, scope, what is out of scope, steps, rollback, "Done when". Show it, wait for "approved".
2. **Read-only checks** of what the change touches on UAT (data that the rules would hide or change, current versions).
3. **Implement** in main, in the smallest diff. Follow the code around you. Regenerate generated files.
4. **Tests that prove it:** each new behaviour has a test that fails before and passes after, and uses the real
   contracts (the zod schemas) rather than mocks where it can. Example:
   `modules/physical-operations-cmms/apps/api/src/work-orders/record-list-contracts.spec.ts`.
5. **Local verification**: the affected tests, type-checks, conversion check, pins, audits and lint (section 7).
6. **Independent Security review**: read-only, by a reviewer other than the producer. For risky releases, use three
   lenses in parallel: scope and authorization; records, data and migrations; contracts, roles, web and supply chain.
7. **Fix findings**, add tests for each, record deferred Lows on the card, and re-verify.
8. **Commit on "commit".**
9. **Release**: copy main's versions of the card's files into the release worktree, regenerate there and confirm
   nothing changes, install with `pnpm install --offline --frozen-lockfile`, build the packages, run the tests and the
   web type-check, then section 4, steps 1–7.
10. **Close**: evidence on the card, NOW.md updated, a short report (at most five bullets) and one next step.

Run from the repository root unless noted. Prefer local binaries; do not run `pnpm install` without `--offline`.

```bash
npx vitest run modules/physical-operations-cmms packages/tenancy-nest packages/contracts packages/module-sdk apps/workflow-platform/__tests__

(cd packages/tenancy-nest && npx tsc --noEmit -p .)
(cd apps/workflow-platform && npx tsc --noEmit -p .)
node scripts/verify-module-conversion.mjs          # S16 kit check
node scripts/module-manifests.mjs                  # audit; --write regenerates
node scripts/verify-migration-pins.mjs
pnpm verify                                        # the full gate (AGENTS.md); one line per step
```

**Lint:** compare each changed file with its committed version, and add no new error or warning. Many files carry
older lint debt; do not reformat untouched code. Method: copy `git show HEAD:<file>` to `zzhead-<name>` with the
same extension in the same folder, run `npx biome check` on both, compare the counts, and delete the copy.

**Known acceptable results:**

  not run.
- The design-tokens audit fails only on the 3 web files owned by other sessions.

## 8. Pitfalls already paid for

- **The Next.js 15 page segment key includes search params.** `router.replace` with new params remounts the page and
  loses form state. To sync the URL without a remount, use `window.history.replaceState` (WI-OI-120az regression).
- **Built-in roles sync only from the roles list.** After a release that changes roles, the owner opens the roles
  list in each kept workspace.
- **SQL with `FOR UPDATE` across outer joins fails in PostgreSQL.** Use `FOR UPDATE OF <alias>`.
- **Parameter numbering:** build SQL with a `values` array and `$${values.length}` after each push. Count again after
  every change.
- **CMMS scope:**
  - `scopePredicates` and `assertWritableScope` in `modules/physical-operations-cmms/apps/api/src/auth/scope.ts`.
    DENIED, an empty list and an overflow all fail closed.
  - Shared (unit-less) rows are visible by default, but requests use `{ shared: false }`.
  - Shared reference data needs `assertWorkspaceWide`.
- **`SCOPE_ENFORCING_MODULES` is `{}`.** Until W1-B, no role can be held at units or places, and the UI hides
  "Chosen units".
- **The conversion check loads `dist`.** Rebuild the SDK and the CMMS API first, or it reports stale results.
- **Journey runs on a loaded host show false blockers.** Check `uptime` before reading a run.

## 9. Report format at the end of each step

At most five short bullets:
- what changed;
- the evidence (exact result lines);
- what is next;
- what the owner must decide, if anything.

Then **one** line with the owner's next action: a single word to reply, one complete command, or "nothing needed from
you now".
