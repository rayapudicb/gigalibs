# WI-OI-121: Assistant source and architecture discovery

Status: **G0–G2 evidence in Review; A1 source import remains entry-gated** (updated 2026-10-09). This is not a legal opinion, accepted ADR, complete SBOM, product implementation, or UAT certification. The owner approved A0b isolated proof and WI-OI-121b A1/A2 conditionally. No upstream source has been copied into GigaLibs.

> 2026-10-09 preview-boundary decision: the owner approved retaining specifically inventoried dormant Core Inspector/Intelligence and the original Chat license-warning code in a development-only candidate, provided an executable SSE-only, same-origin, no-vendor-egress boundary blocks activation. This narrows the earlier target exclusion below for the preview only; it does not approve hosted Intelligence, telemetry, channels, CopilotKit keys, removal/bypass of license warnings or commercial release. Exact source/SBOM/vulnerability evidence and independent Legal/Architecture/Security decisions are still A1 prerequisites.

## 1. Product outcome and boundaries

The first candidate outcome is a read-only answer to “Which work orders are assigned to me, and what are their current status and due date?” for an entitled CMMS member. Each answer must be grounded in the owning CMMS API and resolve only records the caller may open. This waits for the R5 scoped CMMS read path; the UI preview in A2 uses synthetic data and does not claim this outcome. Write tools, arbitrary MCP servers, learning/memory, voice, channels, customer documents, and autonomous actions are excluded from the first release.

GigaLibs owns identity/session, tenant and place scope, entitlement, secrets, Configuration Studio, business facts, governed retrieval (WI-OI-012), and usage/billing (WI-OI-015). The Assistant is a selectable capability module under the ADR-0016 F1 direction, not a new kernel or a route to the parked Python plane. FR-07, FR-14, FR-15, FR-16 and NFR-SEC-006 are acceptance links, not claims that their current owners are complete.

### Source/license gate still open

There is **no approved import file list, transitive SBOM, vulnerability report, complete third-party notice bundle, or binary/asset provenance**. `@copilotkit/license-verifier` is published as MIT according to its [package listing](https://www.npmjs.com/package/%40copilotkit/license-verifier), but the package artifact and its required notices have not been independently audited. The root `package.json` has a `prepare` hook (`lefthook install`); selected package manifests show no install/prepare hook, but transitive packages and `@scarf/scarf` have not been install-script audited. Nothing was installed or executed from Downloads or in GigaLibs. The read-only A0 card cannot produce a truthful **post-pruning** manifest or SBOM, because source edits and an isolated build are needed to find the actual closure. A separately approved A0b proof must record exact include/exclude paths and hashes, resolve the pruned package graph and isolated lockfile, inspect install/postinstall scripts and licenses, assess vulnerabilities, generate an SBOM/notices, and obtain Legal/License approval **before A1 copies source into GigaLibs**. Any restrictive item means stop, not silent substitution.

## 3. Proposed architecture decision (not accepted)

`vendor/copilotkit/` is a versioned, patch-logged third-party source boundary only. `modules/gigalibs-assistant/` would own API, thread/run persistence, model policy, audit/usage and tool adapters; `apps/workflow-platform/` would provide an entitled UI façade. No vendor code may query GigaLibs module tables or hold tenant credentials. No per-tenant fork or runtime DDL. Configuration must use ADR-0019 published overlays and registered action keys; server authority is independent of UI visibility.

The product is separately entitled and potentially sold as **GigaLibs Assistant** even though it is implemented as an optional capability module. An EAM-only tenant does not receive Assistant by default. The A3 module manifest, registered surfaces/actions, minimum Configuration Studio contribution, published tenant policy and server authorization must be proved **before** A4 introduces any live CMMS data. A5 extends the same metadata contribution for advanced settings and commercial controls; it must not create a second configuration authority. A2's isolated chat preview is deliberately not a customer product.

Trusted flow: verified GigaLibs session and entitlement → Assistant server policy (tenant, user, org/place/department, object, classification, action) → owned thread/run transaction → approved model/egress policy → allowlisted **read-only** CMMS API tool → scoped response/citation → audit and idempotent usage record. The CMMS API reauthorizes the caller. Tool arguments and retrieved text are hostile input, not delegated authority. Tenant model choice is disabled by default; external provider egress occurs only under a tenant-approved data-class/region/credential policy. No automatic local↔external fallback.

The Assistant thread store must bind tenant, creator, permitted participants, policy/manifest version, model/provider, classification, retention and run correlation. A stable per-run idempotency key controls usage and retries. Revocation must apply on every resume, message read, tool call, citation open and export. Durable storage and recovery are GigaLibs-owned; the upstream in-memory runner may be used only with synthetic isolated preview data and unreachable customer routes. Provider secrets remain in the existing server-side secret-reference owner, never a prompt, browser field, log or vendor telemetry field.

### Threats and executable negative tests to design before Build

| Threat | Required failing case / owner |
| --- | --- |
| Tenant/user thread crossover or guessed ID | A cannot list/read/resume/clear B's thread; same tenant's nonparticipant also denied, including direct-port calls. Assistant + Security. |
| Scope drift and revocation | Revoked CMMS role, org/site/department change, deleted work order or expired entitlement deny the next tool/read/replay/citation. CMMS + Identity + Security. |
| Prompt/tool injection | Record text cannot request another record, call an unregistered tool, change model endpoint or disclose a secret. Assistant + Security. |
| Vendor/unknown egress | Start, chat, retry, dependency install and shutdown fail closed with DNS/HTTP allowlist logs showing no CopilotKit/Segment/Scarf endpoint; external model endpoint alone is tenant-approved. Platform Operations + Privacy. |
| External/local model data mixing | Tenant A's provider/key/prompt/cache/usage cannot serve tenant B; local-only policy rejects external egress even on outage. Assistant + Privacy. |
| Retention and billing drift | Delete/export/legal hold spans threads, run events, vectors and backups; failed/cancelled/retried runs do not duplicate billable usage. Data Governance + Finance/Product. |

An A2 preview may prove the selected source builds, renders and streams with a synthetic prompt. It cannot prove tenant isolation, approved source licenses, authorized CMMS facts, durable history, billing, no vendor egress, or release readiness. The current explicit sequence is **approved A0b isolated source proof → named Architecture, Security/Privacy and Legal/License decisions → conditionally owner-approved A1 repository import → A2 development-only UI preview under the same card**. Neither A1 nor A2 has begun. R5 remains the sole CMMS Build priority.
