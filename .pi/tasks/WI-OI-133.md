## Goal

Deliver M-RND Operator Inspection Rounds end to end: an administrator publishes and schedules routes, an authorized operator completes them quickly with offline capture and physical checkpoint proof, and exceptions become recoverable, idempotent CMMS actions with visible status and analytics lineage.

**Equipment data decision (owner clarification, 2026-10-30):** the first M-RND build uses CMMS meters for asset-level telemetry context; the existing IoT Gateway can feed CMMS through its meter relay where configured. Operator readings are separately captured and must not inherit the IoT source label. No handheld BLE adapter is required in this build. Vendor-specific probes remain a future enhancement requiring protocol and device proof. NFC/barcode are the physical checkpoint methods; plant geofencing is not a substitute for an indoor asset scan.

## Scope

- **Proposed module boundary:** `M-RND` is the complete first business module under the Frontline Operations family. It owns route/checkpoint versions, assignments, executions, readings and exceptions; it does **not** become a generic empty umbrella for the future M-SOP product. CMMS continues to own assets, meters and work orders; Workforce owns shift/assignment facts; Geospatial owns places; Analytics owns derived facts.
- **May change after approval:** a new `modules/operator-rounds/` module and its manifest, database migrations, domain API, dictionary contributions, web admin UI and tests; versioned contracts/module gateway and `/mobile/v1` BFF routes in this repository; the Rounds feature in the separate `gigalibs_mobile` repository; affected generated catalogue/navigation artifacts; runbooks and evidence.
- **Must not change:** CMMS import/export files, another agent's uncommitted work, secrets, UAT data/services, the web on port 5180, unrelated modules or the fixed deploy order. Cross-module integrations must use reviewed API/event contracts, not direct schema writes.
