# WI-OI-120s (S16): The conversion kit

- **Status:** Proposed (2026-10-06). M1a card of `docs/plans/platform-implementation-plan.md`; after S1
  (WI-OI-120r). Needs the owner's approval.
- **Work item:** WI-OI-120. Evidence goes in `.pi/work/WI-OI-120.md`.
- **Size:** S

## Why

Three modules are on metadata windows: Product Catalogue (U7), Universal Inventory and the Finance general ledger
(U12). Each was converted by hand, and each conversion found the same omissions late: a gateway route missing from
the allow-list (`fiscal-years/standard`), a window field the adapter did not declare, versions read from the wrong
manifest, a page left pointing at the old component. Twenty more modules must follow (ground rule "Metadata first").
They need one template and one check, so a conversion is reviewed against a list instead of rediscovered.

## Goal

A module conversion follows one written template, and one command says whether it is complete.

## Design

1. **The template** (`docs/guides/module-conversion-kit.md`), in the order a conversion is done:
   - the windows, one per surface, generated by a script kept with the module;
   - the record adapters, one per entity, calling the module's own domain service (no table access);
   - the gateway: `records: true` plus every route the windows' actions call;
   - the module page entries in `module.yaml` pointing at the metadata window, and the hand-written component
     removed once nothing points at it;
   - the module roles that grant the windows' permissions (WI-OI-120n);
   - the register rows (canonical owners, access paths) and the journey section;
   - later, when E1 and E2 land, the lifecycle graph and posting policy.
2. **The check**, `scripts/verify-module-conversion.mjs <module>`, fails when:
   - a window field is not declared by its entity's adapter, or the reverse;
   - an action or lookup in a window has no adapter, or no gateway route;
   - a window permission is granted by no role;
   - a converted page still points at a hand-written component, other than the named exceptions;
   - the windows do not publish (S1 rules included).
3. **Proven on what exists.** The check runs on Catalogue, Inventory and Finance, and what it finds is fixed or
   listed. It joins `pnpm verify` for every module marked converted.

## Scope

- **May change:** `docs/guides/`, `scripts/` (the check and its tests), `pnpm verify` wiring, and fixes the check finds
  in the three converted modules.
- **Must not change:** other modules, applied migrations, permission codes, running services.

## Proof

- The check's own tests: one deliberately broken fixture per failure above.
- The three converted modules pass it.
- `pnpm verify`.

## Done when

- [ ] The template is written; the check runs in `pnpm verify` for converted modules.
- [ ] Catalogue, Inventory and Finance pass, or each finding is fixed.
- [ ] Evidence recorded.

## Stop and ask if

- a converted module needs a hand-written page that is not one of the named exceptions.
