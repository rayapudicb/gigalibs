## Owner decisions applied

- M-RND is a standalone Frontline Operations business module. CMMS owns assets, meters and work orders; Workforce owns the resource link; Analytics owns derived facts.
- First build has no BLE adapter or plant geofence proof. A scanned NFC/barcode checkpoint and a manual operator reading remain distinct from timestamped CMMS meter context that may originate at IoT Gateway.
- The entire backend, admin, native mobile and offline journey is required before Built. The owner alone deploys after the fixed groups and accepts the UAT journey.

## Implemented in source so far

- Versioned Rounds contracts and module manifest; tenant and organization scoped route, checkpoint, assignment, run, reading, exception and media APIs; maker-checker route publication; ordered offline sync receipts; audit/outbox and forced RLS migrations 1–5.
- Web admin route builder, assignment and exception board; generated module catalogue, gateway, permission and navigation wiring; `/mobile/v1/rounds` BFF forwarding guarded by the live mobile session and a signed module context.

- Signed CMMS meter-context query and durable corrective-action inbox/relay with tenant-scoped settlement and retry. Signed Analytics reading-fact inbox/relay stores a bounded manual-reading projection without photo content or operator notes.
- Assignment idempotency replay now returns the previously accepted assignment even if the published route later changes or Workforce is temporarily unavailable; a changed request body with the same key is refused.
- Cross-domain identifier contracts now distinguish CUID platform users from UUID Workforce resources and UUID Geospatial places/CMMS asset and meter references; malformed place IDs cannot reach the CMMS UUID cast.
- Evidence staging now requires a separately configured HTTPS public object-store origin for a physical device. Its signed upload URL uses that origin while server-side object reads keep the internal address. Without the public origin, staging answers unavailable before persisting a media row.
- The separate `gigalibs_mobile` source now includes strict Rounds response and command schemas, a session-bound BFF adapter, read-only route and CMMS meter-context screens, and a contained native capability package for camera barcode scanning, NFC tag scanning and SQLCipher availability checks. Expo SQLite `57.0.4`, camera `57.0.6` and `react-native-nfc-manager` `4.2.0` are pinned with native plugins. The screens are not registered in the app navigation, and the offline write runtime remains disabled.
- A contained mobile journal now requires a backup-exclusion check, a 256-bit device-only partition key and SQLCipher before reading or creating draft tables. It uses an exclusive revision compare-and-swap and bounded per-scope draft storage. Key loss for an existing database refuses new provisioning; failed purge retains a blocking reset marker. Strict restart parsing and an ordered coordinator retain a durable dispatch marker before network I/O, preserve uncertainty after a lost response and use original-operation receipt lookup without re-dispatch. These are source components, not an enabled offline runtime.
- A local Expo native module now supplies the Rounds storage directory and sidecar purge: Android uses the app's `noBackupFilesDir`, and iOS excludes its Application Support directory from backup. The key vault and SQLCipher journal consume this native port. Expo autolinking resolves the module for Android and Apple, but no signed binary or physical-device proof exists yet.
- The contained mobile Rounds journal now holds a 1,000-checkpoint path and dispatches consecutive batches of up to 25 commands. Accepted receipts survive a later uncertain batch; that batch remains unknown until original-operation receipt lookup. Pure capture preparation validates physical scan method and exact tag, numeric/choice/boolean value, threshold/photo admission and route-branch order. It cannot establish a committed photo by itself; the server verifies the supplied evidence ID and reclassifies the reading.
- A contained native checkpoint screen renders the immutable view state for scanning, numeric or choice entry, required-photo state, route completion and pending/sending/unknown/accepted/conflict/rejected status. The capture coordinator loads the scoped durable draft, prepares the command against the route, and only returns it after journal save. The status mapper parses receipts before showing accepted. This UI is not wired into app navigation or an offline view model; the photo producer and server-issued offline authority are still absent.
- The pure capture projection now prepares route/journal progress once per download or journal revision and cheaply maps per-keystroke edits to immutable screen state. It discards scan, choice, numeric and photo input whose checkpoint ID no longer matches the active route step; malformed or incomplete readings cannot enable Queue. A local completion is not labelled accepted unless a parsed server completion receipt exists. The native app hook is not wired, and offline capture remains disabled.
- The M-RND [user-journey screen map](../../docs/plans/operator-rounds-user-journey.md) now shows the real administrator, operator and supervisor navigation, each screen's authoritative API, source status and recovery decision points. Web tabs use session permissions: a board-only supervisor no longer triggers `routes.read`, and an account with no Rounds permission sees a no-access state. The route editor has a draft operator-visit preview; dragging a checkpoint remaps branch target positions to the same checkpoint and refuses a backward branch rather than silently changing the path.
- The signed Rounds → Workforce assignment request now includes route unit, site, time zone and assignment window. Workforce rejects a resource without a matching active engagement/position, a working slot that covers the window, or a window blocked by approved absence or site closure. It still checks active human status and the exact platform-user link. A 24-hour maximum bounds the queried window.
- Route schedules now include `windowMinutes`. A route-specific roster stores up to ten Workforce resource/user references with an optimistic version; it does not duplicate Workforce people or shifts. Admin can save that roster and generate one daily/weekly local-date occurrence. The generator handles IANA DST gaps/repeats, stable per-resource request keys, per-operator partial results and a final roster-version check before assignment insertion. `PER_SHIFT` generation refuses without authoritative Workforce shift windows; automatic background orchestration is still open.
- Evidence stage requests now bind the upload digest and ID to one assignment and checkpoint. The server admits only the assigned operator in execution scope on that route; exact committed retries remain available after assignment closure. Capture rejects foreign, uncommitted, legacy-unbound, mismatched or already-used evidence. Migration 7 adds nullable binding fields and a partial unique reading-evidence index; old evidence stays readable but cannot support a new capture. The mobile staging schema carries the same binding fields.
