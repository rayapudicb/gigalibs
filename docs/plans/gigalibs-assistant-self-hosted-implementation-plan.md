## 1. Product decision and what “fork” means

GigaLibs will own, host, customize, maintain, and commercialize a selectable Assistant capability for multiple tenants. A tenant may choose an approved in-house model or an approved external model. No runtime request to CopilotKit is permitted. An external model still receives the minimum authorized payload under that tenant's explicit model policy; “no CopilotKit traffic” is not “no external data processing.”

**Product packaging:** GigaLibs Assistant is a separately entitled and ultimately billable GigaLibs product/SKU. Architecturally it is an optional capability module on the existing GigaLibs kernel, not a second SaaS platform or a required dependency of CMMS. An EAM-only customer receives the standard kernel plus CMMS; Assistant is installed/enabled only if purchased or explicitly included in that customer's plan. Tenant onboarding activates a module entitlement and published tenant configuration, not a per-customer code fork or schema.

The intended implementation is a **curated, pinned source fork inside the GigaLibs repository**, not a blind copy of the upstream monorepo. Proposed boundaries, subject to G2 Architecture and Legal review:

- `vendor/copilotkit/`: only the exact approved upstream source files/packages, their retained license notices, a source manifest, patch log, and an update procedure. No independently runnable GigaLibs business service lives here.
- `modules/gigalibs-assistant/`: the selectable GigaLibs capability module, its manifest, owned API, persistence, policies, configuration contribution, tool adapters, and tests.
- `apps/workflow-platform/`: only the thin, entitled Assistant entry and GigaLibs-facing UI integration. The web shell must not become the model, tenant, or business-data authority.

The temporary “do not copy” rule applies to **A0 discovery**, not the final product. **A1 explicitly copies the approved source into `vendor/copilotkit/`** and GigaLibs maintains the resulting fork. The downloaded whole monorepo is not the import unit: it contains separately restricted `showcase/`, development material and dependencies outside the chosen product boundary. CopilotKit supplies selected interaction/runtime components; the GigaLibs module supplies the multi-tenant product. Merely copying upstream code or rendering chat does not supply GigaLibs tenant isolation, metadata, permissions, business tools or billing.

The adopted source set is **not yet selected or legally cleared**. The candidate pinned release is `v1.77.1` / `ae954754fa60561d31fffe6f2ac94889ac05f4aa`. The owner's downloaded `CopilotKit-main` tree exactly matches later commit `1e9a2af00f8638c18e36862c96a4fd4592c73c50`; its candidate packages and lockfile are unchanged from `v1.77.1`, so the archive can support read-only discovery without becoming an import source. Even `react-core` + `react-ui` + `runtime` pulls a 16-package workspace closure, including Intelligence-named channels, learning, Inspector and 78 distinct direct external dependencies; the lockfile graph reaches 1,128 production/optional snapshot instances before pruning. This is not a curated import list or a complete SBOM. The separately licensed `showcase/` and CopilotKit Intelligence must not be treated as the same MIT source set. GigaLibs will not depend on Intelligence, its license or renewal service, hosted assets, or CopilotKit telemetry. The inherited MIT copyright and license notice must travel with copies/substantial portions as legally required; GigaLibs branding does not erase provenance. Legal counsel decides the approved distribution-notice treatment.

Candidate upstream references: [source packages](https://github.com/CopilotKit/CopilotKit/tree/ae954754fa60561d31fffe6f2ac94889ac05f4aa/packages), [repository license](https://github.com/CopilotKit/CopilotKit/blob/ae954754fa60561d31fffe6f2ac94889ac05f4aa/LICENSE), [separate showcase license](https://github.com/CopilotKit/CopilotKit/blob/ae954754fa60561d31fffe6f2ac94889ac05f4aa/showcase/LICENSE), [TypeScript runtime](https://docs.copilotkit.ai/deepagents/backend/copilot-runtime), [model selection](https://docs.copilotkit.ai/model-selection), and [telemetry](https://docs.copilotkit.ai/a2a/telemetry). ## 4. Per-tenant customization contract

Every tenant uses one maintained GigaLibs code line. A tenant receives Assistant only after its module entitlement is active. **A3 establishes the minimum module contribution and tenant configuration before A4 can touch live business data; A5 extends that same contribution.** Configuration is versioned data under Configuration Studio, not a separate application build. The platform baseline locks security controls; approved module contribution defines safe slots; tenant overlay sets values; role/device/locale variants affect presentation only (ADR-0019). Tenant configuration never expands the user's effective permission or business data scope. The specialized CopilotKit chat component may be mounted on a registered GigaLibs surface; metadata governs its entitlement, placement, labels, settings and registered actions, not every streaming message pixel.

For example, Tenant A may license CMMS without Assistant. Tenant B may license CMMS plus Assistant and publish a local-only model, a CMMS work-order read tool and a 30-day conversation policy. Tenant C may publish an approved external model and a shorter retention policy. B and C run the **same fork and product code**, but have separate configuration versions, credentials, threads, usage and authorized data. A user inside B still sees only work orders permitted by their individual CMMS role and scope. No tenant can publish a new executable tool, bypass a platform lock or turn another tenant's model policy on.

| Tenant-adjustable setting | Authoritative rule |
| --- | --- |
| Assistant enabled state, allowed modules/tools, UI name and locale | Entitlement and registered tool keys are server-enforced; a tenant cannot activate an unentitled module or arbitrary code/MCP endpoint. |
| Local vs approved external model, model/endpoint and region | Tenant admin chooses from platform-approved providers/endpoints and data-classification policy. Default is disabled until an explicit choice and credentials/health check succeed. |
| Provider credentials | Kernel secret-reference system stores and rotates tenant-specific credentials. Neither browser, prompt, logs nor Assistant configuration returns the secret. No tenant shares another tenant's key. |
| Prompt/system guidance and response format | Versioned, reviewed templates in bounded slots; tenant text cannot override platform security/tool policy or inject executable code. Record active version on each run. |
| Knowledge sources and retrieval | Only authorized, classified, versioned documents are indexed. Retrieval rechecks the requesting user's scope, including after role revocation or document deletion; cache/vector partitions cannot leak across tenants. |
| Thread retention, export and deletion | Tenant policy may narrow, but not weaken, legal minimums/holds. Thread, message, run, vector and audit deletion/export have owner, schedule and verification evidence. |
| Quotas, cost limits and charges | Existing entitlement and billing owners define cap and price policy. Assistant emits idempotent usage/estimated cost with provider identity; billable treatment of BYO/local models is a Product decision. |

The minimum trusted request path is: `signed-in GigaLibs user → entitled Next/BFF route → Assistant module → verified policy and module-owned thread → approved model + allowlisted read-only tool → owning business API → cited response + audit/usage`. Any model-supplied tool arguments are untrusted input. Business APIs repeat authorization; the prompt never grants rights.

## 5. Evidence matrix for the first customer-facing journey

Candidate outcome: a permitted CMMS user asks for their assigned work orders and receives current status, due date and authorized record links. This is a **candidate**, not a claim that the needed endpoint or R5 scope is complete. If source APIs cannot prove the caller's organization/place/department and record permissions, the journey waits; do not use direct SQL or a broader fallback.

| Check | Required proof |
| --- | --- |
| Source and privacy | Exact fork SHA/source manifest/license notices; no CopilotKit-bound DNS/HTTP during start, chat, tool, retry and shutdown; outbound allowlist blocks unknown hosts. The telemetry environment flag alone is insufficient. |
| Identity and tenancy | Authenticated tenant A member sees only authorized A records/threads; B IDs, revoked member, missing entitlement, wrong org/site/department and guessed thread ID are denied server-side. |
| Data truth | Work-order status comes from the CMMS owner and matches direct authorized read; response links/citations resolve only for permitted users; stale/unavailable source is marked, not invented. |
| Models | Same bounded journey runs against approved local and external sandbox models with synthetic records; no provider is silently substituted; credentials are never returned or logged. |
| Persistence and operations | Conversation survives reload/restart; streaming reconnect/cancel has explicit semantics; failure/retry cannot duplicate a tool effect or usage charge; retention, deletion and restore are demonstrated. |
| Commercial isolation | Two tenants have independent model, prompt, tool, retention and cap settings; an over-cap tenant cannot bypass the cap by switching routes/models; usage reconciles to provider runs and billing policy. |
| User experience | Playwright covers first-use, empty, streaming, citation opening, denied, provider outage, quota reached and retry; keyboard/screen-reader and mobile layout are reviewed. |
